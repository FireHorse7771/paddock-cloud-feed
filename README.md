# PADDOCK cloud feed — підготовлений компонент

Цей компонент читає лише публічні кінні картки Pokerbet через звичайний Chromium, незалежно від комп'ютера власника. Логіну, кліків по коефіцієнтах та розміщення ставок немає. Тут немає приватних даних, моделей, історичних результатів або секретів PADDOCK.

Компонент опубліковано в FireHorse7771/paddock-cloud-feed. Перший реальний GitHub Actions запуск 10.10.2026 завершився успішно: 44 картки з WIN-котируваннями пройшли незалежний raw-аудит у runner; огляд частковий (complete_scan=false). Автоматичного розкладу й передавання на сайт немає. Успішний HTTP200 сторінки сам по собі не підтверджує отримання котирувань.

Підготовлено `.github/workflows/source-check.yml`: лише ручний `workflow_dispatch`, стандартний `ubuntu-24.04`, максимум 10 хвилин, доступ репозиторію тільки на читання. Розкладу, запусків при push і передавання ключа PADDOCK немає. Всі файли цього компонента повинні бути в корені окремого репозиторію; увесь проєкт PADDOCK завантажувати не потрібно. Після створення акаунта та погодженої публікації компонента перша перевірка запускається в Actions → «PADDOCK — перевірка джерела» → Run workflow. Фактичний перший run: https://github.com/FireHorse7771/paddock-cloud-feed/actions/runs/38053301414 , commit 7abdf5b2f77ef7322e45d64a0cae35051835389b, тривалість 2 хв 10 сек; 5 офлайн тестів також пройшли в runner. Картки спостерігалися від 12:49:07 UTC / 15:49:07 Київ. Це одинична перевірка доступу, а не доказ постійної роботи чи повного покриття.

Для першої перевірки на стандартному Linux runner:

```sh
python -m pip install -r requirements.txt
python -m playwright install --with-deps chromium
python cloud_once.py
```

За замовчуванням нічого не публікується. Передавання дозволяється окремим `--publish` лише після незалежної raw-перевірки. Ключ береться з repository secret `PADDOCK_FEED_WRITE_KEY`; його не можна додавати у файли, Git чи журнали. Секрет до GitHub ще не передавався.

Між запитами перевіряється бюджет 110 секунд; жорсткий timeout всього collect — 170 секунд. Максимум 12 іподромів, 60 карток і два читачі. Помилки та часткові огляди залишаються явними. Перевіряються повні WIN-склади та точні ціни з сирих DOM-блоків; публікація перевіряє тотожну відповідь і повторне читання із сайту. Реальні ставки й зіставлення з прогнозом не підтверджуються.

Стандартні GitHub-hosted runners безкоштовні для публічних репозиторіїв; приватні мають квоти, larger runners платні. [Офіційні умови](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).

Підтримуваний scheduled інтервал починається з 5 хв і може затримуватися; наш поріг свіжості цін 180 сек не збільшується. [Документація розкладу](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule). За потреби безперервної свіжості потрібна окрема перевірена архітектура; цей пакет не обіцяє її.

Наступне: зберігати відтворюваний raw-архів у хмарі, потім окремо погодити мінімальний доступ для передавання на PADDOCK, перевірити authorized write/readback і повторний цикл; тільки після цього вмикати розклад. Налаштування ESET на ПК для цього не змінюються.

Оновлення 11.10.2026: `--evidence evidence/public-source.zip` створює архів лише після незалежної перевірки. У ньому тільки сирі публічні WIN-картки, receipt, список пропусків, audit без локальних шляхів та SHA-256 кожного файла. Сторонні файли з робочої папки не потрапляють в архів; максимум 8 MiB до стиснення. Повторний запис наявного ZIP заборонено. У workflow додано збереження цього одного ZIP через офіційний actions/upload-artifact@v7 на 1 день. Це коротке зберігання для перевірки; після закінчення терміну потрібно мати власну завантажену копію. Перший run 10.10 був без архіву, його сирі картки відновити з журналу не можна.

Повторна перевірка завантаженого ZIP: розпакувати в окрему папку, прочитати `scan_*/receipt.json`, додати `receipt_sha256` із `manifest.json` і викликати незалежний `verify_receipt.verify(value, folder)`. Хеші та розміри всіх файлів також наведено в manifest. Пропуски та часткове покриття не зникають після експорту.

Перед Chromium ключ видаляється з успадкованого середовища, щоб дочірній браузер його не отримував.

Поточний стан 11.10.2026: попередні абзаци описують історичні етапи. За окремою згодою власника новий ключ тільки для котирувань збережено в зашифрованому repository secret. Ручний workflow тепер виконує `--publish`; автоматичного розкладу немає. Перша спроба передачі зупинилася до запису на сайт, тому доставку ще не підтверджено. Додано безпечну діагностику кількості прочитаних карток і причин пропусків без тексту помилок або секретів. Порожній огляд не публікується. 9 локальних перевірок пройшли. Успішний архів попереднього запуску містить 2 картки Австралії та 25 цін, незалежно повторно перевірені після завантаження.

[GitHub Free включає 500 MB artifact storage](https://docs.github.com/en/billing/concepts/product-billing/github-actions), спільного з GitHub Packages. Цей ручний тест обмежений 8 MiB/1 днем; регулярний розклад із такими архівами не ввімкнений і потребує окремого обліку квот.
